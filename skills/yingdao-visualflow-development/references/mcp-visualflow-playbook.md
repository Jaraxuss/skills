# VisualFlow MCP 开发手册

## 1. 预检与流程设计

修改前读取：

- 当前应用信息、保存状态和活动流程。
- 全部流程的 `flow_id`、类型、主流程标记及块数量。
- 目标流程参数、现有指令块详情、可见变量和必要资源。
- 涉及网页或应用操作时，需求中指定的选择器和目标系统前提。

按实际业务执行顺序设计流程。只有多个相邻步骤互不依赖且工具支持安全批量操作时才批量修改；不要为了减少调用而牺牲块顺序和作用域正确性。

## 2. 发现指令原型

- 在插入指令前读取影刀 MCP 提供的 `knowledge/visual-blocks/block_catalog.md` 和相关 `block_detail.md`，或使用 Wiki 搜索定位对应指令文档。
- 使用文档中的准确 `prototype_name`。不要按中文指令名称、记忆或相似功能猜测原型。
- 需要选择器时，优先使用需求或现有流程给出的准确名称。仅在名称未知时使用选择器列表做字面过滤；零结果或多个候选都应停止猜测并询问用户。
- 指令设置界面依赖账号、工作簿或其他动态数据时，使用插入结果中的 `dynamic_data_for_llm` 候选及其成组字段，不拆开拼接不兼容值。

## 3. 插入与填写

- `flow_edit_blocks` 是插入和删除指令实例的唯一入口。插入时提供执行位置、准确原型和简短英文语义标签；该标签用于本次块映射，不会成为 Studio 中的持久注释。
- 插入操作只创建块，不填写设置。使用返回的 `block_id` 调用 `flow_fill_blocks`。
- 普通字段放入 `fills`，同一块在一次调用的 `fills` 中只出现一次。
- 重复结构字段使用顶层 `group_fills`；共享字段放 `fixed`，变化字段放等长的 `columns` 数组。
- 普通字符串表示字面量；空字符串使用显式文本形式。变量、表达式、选择器、数组和对象使用对应语义包装，不把变量名当普通文本填入。
- 长多行代码或文本直接传字符串，不套只为显式空文本设计的包装。
- 一个块填写失败不代表整批都失败。检查 `fill_errors`，仅重试失败的 `block_id`；`validation_errors` 是当前流程整体遗留问题，应单独处理。

## 4. 变量、参数和作用域

- 填写变量引用前使用 `flow_list_variables` 检查变量名、来源、定义位置和可见范围。
- 循环、条件、异常处理内部变量不能逃逸到外部；需要跨作用域使用时，在合法外层建立明确输出或赋值。
- 用 `flow_write_parameters` 管理流程参数。集合使用 `type=any`。
- VisualFlow 的计算型 Out 参数不要设置初始化值；产生它的块输出必须与 Out 参数同名。
- 代码片段中创建的变量无法被静态作用域分析识别，因此不要让关键数据契约依赖隐藏变量。

## 5. 子流程调用

使用 `process.run` 时：

1. 调用方和目标流程必须不同，避免递归调用。
2. 先确认目标流程的 In/Out 参数；设置 `process` 后，以更新表单中的字段为准。
3. 只通过 `arguments.<参数名>` 填入子流程输入。
4. 使用 `output_properties.process_result` 中返回的精确表达式引用子流程输出；`outputs` 只保存承接结果的变量名。
5. 切换目标流程时，已有参数名必须符合新流程契约，不沿用旧目标的字段。

## 6. 验证与调试

1. 修改后用块详情复查顺序、原型、字段实际值和输出变量。
2. 使用 `app_save` 保存并编译，再用 `diagnostics_snapshot` 处理静态错误。
3. 使用明确 `flow_id` 调用 `app_run`。运行返回终态时直接使用结果；仅在超时时用同一 `run_id` 等待。
4. 用户暂停或停止时立即停止自动操作并询问下一步。
5. 运行失败时先读取诊断和日志；需要块级输入输出时，再读取目标 VisualFlow 的变量快照。
6. 修复应针对证据指向的问题，不通过重复运行碰运气，也不重写无关块。

最终核验流程输出、页面或文件副作用、重复执行行为、异常路径和人工介入点，并记录未能在当前环境验证的步骤。

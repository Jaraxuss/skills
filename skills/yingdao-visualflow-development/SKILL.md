# 影刀 VisualFlow 规范开发

把开发就绪的需求实现为结构清晰、变量作用域正确、可运行和可维护的影刀 VisualFlow。

## 开始前

1. 确认用户已授权修改当前影刀应用，并取得需求文档或等价的输入、输出、规则、异常及验收契约。关键歧义会改变流程分支或外部副作用时先确认。
2. 阅读 [VisualFlow MCP 开发手册](references/mcp-visualflow-playbook.md)。
3. 通过 MCP 读取当前应用、流程、资源、目标流程参数、现有指令块和可见变量。不要仅根据界面焦点或相似名称选择目标。

## 实现流程

1. 复用合适的现有 VisualFlow，或创建 `kind=visual` 的新流程。先按业务阶段设计指令顺序、分支、循环、异常和子流程边界。
2. 从影刀 MCP 提供的指令目录和详情中查找准确原型，不猜 `prototype_name`、字段名、选择器名或动态候选值。
3. 先插入指令，再用返回的 `block_id` 和表单填写字段。普通字段、重复结构字段、变量、表达式、选择器及集合使用各自正确的语义形式。
4. 在引用变量前检查执行顺序与作用域。分支、循环和异常块内部变量不得被假定可以在外部使用。
5. 需求要求可视化维护时，优先使用语义清晰的原生指令块；不要把主体逻辑藏进单个代码片段。只有确无合适指令且用户接受时才使用少量代码，并说明原因。
6. 将必要的需求文档、模板和运行资源加入应用。调用子流程时显式填写参数并使用 MCP 返回的输出引用。
7. 保存编译、检查诊断、运行目标流程，并结合运行结果、日志和变量快照定位问题。运行超时时等待同一 `run_id`，不得盲目重跑。

## 完成标准

- 指令顺序、分支、循环、变量作用域、参数、资源和选择器与需求一致。
- 静态诊断无错误，运行结果和可观察业务产物通过验证。
- 块详情中没有依赖未落地的默认值、缺失必填字段或猜测出来的原型与字段。
- 交付摘要列出流程结构、参数、资源、关键选择器、测试结果和未验证步骤。

## 边界

- 不把 VisualFlow 请求偷换成主要由 CodeFlow 或大段代码片段实现。
- 不扫描或扩展匹配选择器名称；零结果或多结果时先让用户确认准确目标。
- 不自行执行超出需求范围的外部提交、删除、发送或生产写入。
- 用户只要求分析或诊断时，不顺带修改流程。

# 管理后台交付验收

实施或重构管理后台时使用本清单；纯方案讨论无需逐项执行。

## 信息架构

- 一级页面只出现一次主标题；侧栏、顶栏、面包屑和正文没有同义重复。
- 列表页默认有内容，筛选是辅助；新建、详情、审核分别使用合适的页面层级。
- 页面能容纳后续模块，不依赖把新卡片持续堆到首页。

## 前后端契约

- 分页、筛选和排序由后端完成，并有边界测试。
- 列表响应不读取全部历史版本、大型向量或二进制文件。
- 详情接口不泄露服务器绝对路径、内部存储路径或其他租户数据。
- 状态切换幂等；失败时不留下半成品。

## 版本化数据

- 切换旧版本后，较新版本仍存在且可再次选择。
- 从旧版本派生时，新版本号取历史最大值加一。
- 停用不清空当前版本，不修改历史版本内容；启用后恢复加载当前版本。
- 来源信息不完整时显式说明，不能通过模糊匹配补造。

## 浏览器体验

- 至少检查常见桌面宽度和窄屏布局。
- 验证键盘焦点、加载、空状态、错误提示、危险操作确认和刷新后的状态保持。
- 用浏览器实际走通主要流程；不要只以 TypeScript 构建通过代替交互验收。

## 工程与 Git

- 运行与改动风险相称的后端测试、前端构建和静态检查。
- 检查 `git diff --check`、改动范围和未追踪文件，保留用户原有内容。
- 只暂存本次完成的文件；默认不提交，并给用户一条可审核的 Conventional Commit message。

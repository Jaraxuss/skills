# 飞书内部案例沉淀文档模板与写作反例对照

本文档规定 `yingdao-copilot-case-doc` 输出飞书云文档（XML 格式）的章节骨架、SVG 流程图画板规范以及语态红线。

---

## 一、语态红线：内部 CSM 经验分享腔 vs 严禁出现的“AI 免责声明腔”

沉淀文档的读者是**影刀内部其他 CSM、售后与培训讲师**。他们打开文档的唯一目的是：**看懂这个行业场景怎么回事、判断能不能拿去给自己的客户参考、照着把流程搭出来**。

| 维度 | ❌ 严禁出现的“AI 防杠/审计免责腔” | ✅ 推荐的“内部 CSM 实战沉淀腔” |
| :--- | :--- | :--- |
| **积分与耗时** | “397 积分是本次搭建的消耗，不等于运行成本或节省工时；1小时33分包含用户等待时间，不等于纯 AI 开发耗时。” | “构建消耗：397 积分（含网页探索、流程构建、报错自修复与参数弹窗封装，总历时约 1 小时 33 分钟）。” |
| **业务核验** | “业务老师回复同时段数据与人工一致；但不能把这次对比扩展成所有周期均已验收，资料没有证明长期稳定运行。” | “经客户业务老师实测比对，反馈‘同时段范围数据与人工结果 100% 一致’；日常按每月结算周期输入起止日期即可运行。” |
| **规则分支** | “用户本次选择整体剔除未登记公司名；这是本次构建中人工选择的规则，不应推断为所有类似场景都可以直接剔除。” | “针对样例中出现的 5 个未登记公司名，AI 主动暂停弹窗询问，本次按业务确认口径统一剔除并输出到运行日志备查。” |
| **技术突破** | “该跨月能力基于当时网站的实测，不视为所有网站的通用规则；网站控件变化时应重新核对。” | “避坑提醒：‘JS 赋值突破跨月限制’依赖目标网站后端未做单月强校验；复用到其他商业网站时，建议让 AI 先实测核对跨月导出条数。” |
| **日志截图** | “图 6｜修正调用参数后重新运行；截图是 AI 运行记录，不替代业务核对。” | “图 6｜AI 自动定位并补齐子流程调用传参后重新运行，单月样例成功清洗输出 587 条记录。” |

## 二、文档整体章节结构（XML 骨架）

必须采用**中文手写序号模式**（`<h1>一、...</h1>` 搭配 `<h2>（一）...</h2>` 与段落内 `<b>1. ...</b>` 或 `<ol>`），严禁在 `一、` 下混用 `1.1`。

### 首屏：一句话速览 + 双栏检索画像

```xml
<title>Copilot落地场景总结｜[客户名称]：[业务场景名称]</title>

<callout emoji="💡" background-color="light-blue" border-color="blue">
  <p><b>场景一句话速览：</b>针对[行业+部门]在[具体业务场景]中面临的[核心痛点]，通过<b>影刀 AI 流程助手（Copilot）</b>，仅用“[输入方式，如：自然语言步骤 + N 份业务样例表]”，经 [X] 轮主指令与 [Y] 次问答交互（消耗 [Z] 积分），即可自动完成[核心动作链路]，实测结果与人工处理 100% 一致。</p>
</callout>

<grid>
  <column width-ratio="0.5">
    <callout emoji="🏷️" background-color="light-gray" border-color="gray">
      <p><b>基础检索标签</b></p>
      <ul>
        <li><b>适用行业 / 部门：</b>[如：医药行业（药企） / 商务部]</li>
        <li><b>业务场景：</b>[如：商业公司网载流向下载、多维规则清洗与标准化转换]</li>
        <li><b>涉及系统：</b>[如：供应商查询门户（Web）、Excel、用友 NC]</li>
        <li><b>当前状态：</b>[如：已完成搭建并通过业务同周期真实数据核验，用于客户 AI 实操带教]</li>
      </ul>
    </callout>
  </column>
  <column width-ratio="0.5">
    <callout emoji="🤖" background-color="light-gray" border-color="gray">
      <p><b>AI 流程助手构建画像</b></p>
      <ul>
        <li><b>运行环境：</b>[如：Windows 11 + 影刀 RPA 6.3.39 + Chrome]</li>
        <li><b>使用模型：</b>[如：DeepSeek V4.1 Flash]</li>
        <li><b>构建消耗：</b>[如：397 积分（含探索、构建、调试与弹窗封装）]</li>
        <li><b>交互轮次：</b>[如：2 次用户主指令 + 8 次 AI 澄清问答（共确认 13 个细项）]</li>
      </ul>
    </callout>
  </column>
</grid>
```

### 模块一：需求背景与客户痛点

- **`<h2>（一）需求背景</h2>`**：
  - 先讲清**行业共性业务逻辑**（这个名词是什么、业务人员为什么要干这件事、数据从哪来到哪去）。
  - 再讲**本次客户触发契机**（如：已有部分流程但剩余站点太多、同事休假工作压力大、希望借助 AI 流程助手降低业务人员自主搭建门槛等）。
- **`<h2>（二）客户痛点</h2>`**：
  - 用 `<ol>` 提炼 3～4 条具体痛点，兼顾**人工操作痛点**（跨系统/跨月限制、Excel 多条件筛选繁琐易错、数据量大）与**传统 RPA 搭建痛点**（一家商业一套规则、嵌套网页或复杂表格逻辑让非技术业务人员难以上手）。

---

### 模块二：解决方案与演示视频

- **`<h2>（一）整体方案设计（业务与 RPA 流程图）</h2>`**：
  - 先用 `<ul>` 说明整体编排架构（例如：`VisualFlow 可视化主流程` 负责交互弹窗与网页自动化，方便业务看懂维护；`CodeFlow Python 子流程` 负责复杂 Excel 规则清洗与模板写入）。
  - 紧接着插入 `<whiteboard type="svg">` 全链路流程图（推荐采用 4 阶段横向卡片式 SVG 布局，底部配深色实测数据横幅，见下方第三节 SVG 模板）。
- **`<h2>（二）演示视频（AI 流程助手真实搭建与运行实录）</h2>`**：
  - 先用 `<ul>` 列出视频的 3～4 个关键时间戳看点（如 `00:24 – 01:04｜亮点一：AI 自动探索网页并突破跨月限制`）。
  - 紧接着用 `<figure view-type="Preview"><source path="@./..." name="..."/></figure>` 内嵌演示视频。
- **`<h2>（三）核心需求规格与数据流转细节</h2>`**：
  1. **输入资料与运行参数清单**：表格展示输入文件与弹窗参数，并用 `<figure view-type="Card"><source path="@./..." name="..."/></figure>` 挂载脱敏后的需求规格文档（`.md`）和空白标准模板（`.xlsx`）。
  2. **核心业务清洗/判断规则表**：贴出客户原始规则局部截图（`<img path="@./..."/>`），并用表格完整列出每条规则的判断条件与动作。
  3. **目标模板字段映射与命名规范**：表格列出目标列、标准字段名、取值/映射规则及格式保真要求（如保留负数冲红、批号保留前导零、日期格式化等），并贴出最终封装的《运行参数对话框》截图。
  4. **同行业扩展规则参考（Callout）**：用 `<callout emoji="📌" background-color="light-yellow" border-color="yellow">` 补充客户在沟通中提到的同行业高频扩展规则（即使本例未涉及，也能极大赋能其他 CSM 对客交流）。

---

### 模块三：方案价值（人工执行 vs RPA 执行对比）

- **`<h2>（一）全流程人机执行效率与质量对比</h2>`**：
  - 必须包含一张 4 列对比表（`对比维度 | 传统人工操作方式 | 影刀 RPA 自动执行（AI 辅助搭建） | 核心价值体现`），覆盖数据获取、复杂规则清洗、异常/未知数据兜底、标准模板映射、流程扩展门槛 5 个维度（若客户已提供明确的人工耗时 vs RPA 耗时，直接作为首行加入对比表）。
- **`<h2>（二）真实数据实跑与客户核验结果</h2>`**：
  - 列出单月/跨月试跑的真实数据漏斗（原始导出多少条 $\rightarrow$ 规则剔除多少条 $\rightarrow$ 最终写入多少条）与业务老师的核验原话，并附上最终运行日志截图。

### 模块四：AI 流程助手搭建环境与参考提示词

- **`<h2>（一）运行环境与构建消耗参考</h2>`**：双列表格汇总操作系统、影刀版本、底层模型、流程架构、积分消耗与耗时、交互轮次。
- **`<h2>（二）参考提示词（可直接复用模板）</h2>`**：
  - 按实际轮次展示完整提示词（放入 `<pre lang="markdown" caption="..."><code>...</code></pre>`），**必须去掉本地机器特有的绝对路径（如 `Z:\Desktop\...`）及真实密码**，使其成为其他 CSM 可直接复制改写的通用模板。
- **`<h2>（三）CSM 现场提需的 3 个实战技巧</h2>`**：
  - 结合本案提炼可复用的提需方法论（如：① 复杂规则放 Excel 附件、Prompt 只讲匹配骨架；② 埋入“没写到的情况先提醒我”防止 AI 瞎猜；③ 先跑通核心链路再套壳交互对话框）。

---

### 模块五：踩坑总结与避坑指南

从会话日志与开发录屏中提炼 3～4 个真实坑点（涵盖**业务规则缺口坑、网页控件/DOM 坑、VisualFlow/CodeFlow 传参或代码调试坑、影刀交互组件限制坑**）。每个坑点采用统一结构：

```xml
<h2>（一）坑点 1：[一句话点明坑点本质]</h2>
<ul>
  <li><b>踩坑现象：</b>[具体发生了什么问题、数据表现或报错信息是什么]</li>
  <li><b>解决过程：</b>[AI 是如何发现、弹窗询问或读取日志自动修复的，人工做了什么决策]</li>
  <li><b>避坑建议：</b>[其他 CSM 在客户现场遇到同类问题时，应该在提示词或操作上注意什么]</li>
</ul>
<img path="@./..."/>
<p align="center">图 X｜[清晰说明截图展示的证据或状态]</p>
```

## 三、SVG 全链路流程图画板规范（`<whiteboard type="svg">`）

- 视图尺寸推荐：`viewBox="0 0 980 520"`。
- 布局推荐：顶部主副标题 + 中部 4 列阶段卡片（每列宽约 `200~225px`，顶部带渐变色标题栏，内部纵向排列 3 个步骤框并用垂直箭头连接，卡片之间用水平箭头连接）+ 底部深色实测数据横幅（`rect x="24" y="444" width="932" height="54" rx="10" fill="#1E293B"`）。
- **飞书画板重排防溢出铁律**：
  - 文字必须使用 `<text>`，严禁使用 `<pattern>` / `<clipPath>` / `<mask>`。
  - 卡片内单行中文字符控制在 14～16 字以内（字号 `11~13px`）；底部横幅单行总字数控制在 55 字以内（字号 `12px`），避免飞书画板按 Noto Sans SC 重排时文字超出矩形左右边界。
  - 创建文档后必须通过 `lark-cli whiteboard +export --as user --whiteboard-token <token> --output-type preview --output ./wb_preview.jpg` 导出预览图并查看检查！

# 影刀 AI 流程助手（Copilot）内部案例沉淀文档生成

将一次真实的影刀 AI 流程助手（Copilot）应用搭建、调试与业务核验过程，转化为**面向影刀内部 CSM、售后顾问与培训讲师**的高质量飞书案例沉淀文档。

核心目标：**让其他 CSM 检索到该文档后，30 秒内看懂行业痛点与方案价值，能直接拿流程图和演示视频给客户参考，并能照着提示词与避坑指南在客户现场复现。**

---

## 一、输入材料盘点与解析（Step 1）

用户通常会提供以下 4 类上下文材料（部分已在当前工作区或对话上下文中）：

1. **影刀 AI 流程助手会话文件（`copilot-session-*.json`）**
   - **必做动作**：首先运行本 Skill 内置解析脚本，提取精确构建画像：
     ```bash
     python3 <skill-dir>/scripts/parse_copilot_session.py "<path/to/copilot-session-*.json>"
     ```
   - 从输出 JSON 中获取：
     - 影刀客户端版本（`shadowbot_versions_detected`，如 `6.3.39`）
     - 构建时间跨度与总耗时（`timeline`）
     - 用户正文指令轮次与完整原文（`user_prompts`，已自动剥离 `[[SHADOWBOT_RUNTIME_CONTEXT]]`）
     - AI 结构化提问轮次、问题总数、各选项及用户的实际选择（`questions_and_answers`）
     - 流程编排架构（`VisualFlow` 主流程 / `CodeFlow` 子流程调用记录）与运行报错/修复日志（`run_and_log_events`）

2. **需求文档与业务样例表格（`.md` / `.xlsx`）**
   - 读取已梳理的需求规格文档、输入配置表、源数据导出样例与目标标准模板。
   - **安全与脱敏铁律**：客户配置表（如含网址、账号、密码的 `.xlsx`）中的**登录密码严禁写入文档正文或截图**，也不要把含真实密码的原表直接作为飞书附件上传；优先上传脱敏后的需求规格说明（`.md`）与空白标准导入模板（`.xlsx`）。

3. **与业务老师的沟通记录（会议转写 `.md` / 聊天记录 / 客户沟通知识库）**
   - 读取用户提供的会议转写稿，或按需使用 `customer-communication-knowledge` 检索飞书/微信沟通原文。
   - 重点提取 4 类信息：
     - **触发契机与业务背景**：客户部门平时怎么做、为什么现在要用 AI 流程助手（如负责同事休假、剩余省份/站点太多来不及逐个搭等）。
     - **人工操作与自主搭建痛点**：业务老师亲口吐槽的繁琐点（如网站不能跨月要下两次合并、Excel 筛选反选极其复杂、嵌套网页难抓等）。
     - **同行业扩展规则**：沟通中提到但本例暂未涉及的行业共性分支（如其他商业需按生产厂家过滤本厂曾用名、按特定剂型/发货组织拆表等），作为文档中的“行业扩展干货”沉淀下来。
     - **业务验收原话**：业务老师核对输出文件后的反馈原话（如“同时段范围数据与人工结果一致”）及日常业务周期说明。

4. **运行录屏 / 完整开发录屏 / 培训演示视频（`.mp4` / `.mov`）与关键截图**
   - **已有剪辑成片与截图**：若工作区已有浓缩演示视频（如 2～3 分钟的培训展示 `.mp4`）和关键截图，直接纳入文档。
   - **仅有原始长录屏**：使用 `ffmpeg` 从录屏中抽取 5～6 张高信息量关键截图保存到本地目录：
     1. 客户原始规则表 / 源数据表结构截图（注意裁除密码行）
     2. 最终封装的运行参数对话框截图
     3. 最终实跑成功的运行日志截图（显示输入条数、剔除条数、输出条数与文件路径）
     4. AI 探索网页/提出新方案（如 JS 跨月查询）或发现规则缺口的问答弹窗截图
     5. 端到端调试报错画面及 AI 自动修复后的成功日志截图
   - 若用户尚未剪辑短演示视频且希望在文档中嵌入精简视频，可先询问是否需要从完整录屏剪辑 2～3 分钟无声字幕版演示视频；若用户已有运行录屏可直接上传，则直接内嵌。

## 二、最小必要信息确认（Step 2）

`copilot-session-*.json` 通常不包含**底层大模型名称**（如 `DeepSeek V4.1 Flash`）和**本次构建消耗积分数**（如 `397 积分`）。

- 在动笔生成文档前，检查上下文是否已有这两项数据，以及是否有明确的人工节省工时数据。
- 若缺失，**合并为一次简短提问**向用户确认（例如：“请确认本次搭建使用的**模型名称**和**消耗积分数**？如果人工单次/每月节省时长暂无统计，我将直接用《人工 vs RPA 全维对比表》+ 实测数据量来体现方案价值。”）。
- 严禁拆成多轮碎问，也不要自行编造积分数或节省工时。

## 三、文档结构与语态规范（Step 3）

详细 XML 骨架、SVG 画板模板与正反例对照见 **[references/doc-template.md](references/doc-template.md)**（动笔前必读）。

### 1. 语态铁律：去“免责声明腔”，写内部 CSM 实战人话
- **严禁出现 AI 审计/防杠自证话术**：全文禁止出现*“XX积分不等于运行成本或节省工时”*、*“不能把这次对比扩展成所有周期均已验收”*、*“资料没有证明长期稳定运行”*、*“这是本次人工选择的规则，不应推断为所有类似场景适用”*、*“截图是 AI 运行记录，不替代业务核对”*等别扭表述。
- **转换为正向复用建议**：涉及适用前提的提醒（如 JS 绕过前端跨月限制、特定未登记公司名的剔除策略），统一放进第五章《踩坑总结与避坑指南》的**“避坑建议”**中，以老练 CSM 给同事支招的口吻写出。
- **拒绝调试流水账**：不要在前半部分堆砌单次调试了多少回、贴多张重复日志；前半部分聚焦**业务全貌、流程图、演示视频、完整规则映射表与人机价值对比**，后半部分聚焦**环境、可复制提示词、提需技巧与 4 大实战坑点**。

### 2. 六大核心模块布局
1. **首屏：一句话速览（Callout）+ 双栏检索卡片（Grid）**
   - 左栏：基础检索标签（适用行业/部门、业务场景、涉及系统、当前状态）。
   - 右栏：AI 流程助手构建画像（运行环境版本、使用模型、构建消耗积分、交互轮次）。
2. **一、需求背景与客户痛点**
   - `（一）需求背景`：行业业务全貌 + 客户本次触发契机。
   - `（二）客户痛点`：3～4 条痛点（涵盖网页/跨期限制、Excel 多维规则复杂易错、多商业/多站点人工搭 RPA 门槛高等）。
3. **二、解决方案与演示视频**
   - `（一）整体方案设计（业务与 RPA 流程图）`：说明编排架构（如 `VisualFlow 主流程 + CodeFlow 子流程`），并嵌入 **SVG 全链路流程图画板（`<whiteboard type="svg">`）**。
   - `（二）演示视频（AI 流程助手真实搭建与运行实录）`：列出视频时间戳看点导览，并用 `<figure view-type="Preview"><source .../></figure>` 直接内嵌演示视频。
   - `（三）核心需求规格与数据流转细节`：
     - 输入资料与运行参数表 + 挂载脱敏需求规格文档（`.md`）与空白标准模板（`.xlsx`）附件卡片（`<figure view-type="Card">`）；
     - 核心业务清洗/判断规则表 + 客户规则原表局部截图；
     - 目标模板字段映射与文件命名规范表 + 运行参数弹窗截图；
     - **同行业扩展规则参考（Callout）**：沉淀沟通中挖掘到的同行业共性扩展规则。
4. **三、方案价值（人工执行 vs RPA 执行对比）**
   - `（一）全流程人机执行效率与质量对比`：4 列对比表（对比维度、传统人工操作方式、影刀 RPA 自动执行、核心价值体现），覆盖数据获取、复杂规则清洗、异常兜底、模板映射、搭建门槛 5 大维度。
   - `（二）真实数据实跑与客户核验结果`：列出试跑数据漏斗（原始条数 $\rightarrow$ 剔除条数 $\rightarrow$ 写入条数）、业务老师验收反馈原话，并贴出实跑成功日志截图。
5. **四、AI 流程助手搭建环境与参考提示词**
   - `（一）运行环境与构建消耗参考`：环境、版本、模型、架构、积分与耗时、交互轮次汇总表。
   - `（二）参考提示词（可直接复用模板）`：按实际指令轮次放入 `<pre lang="markdown">` 代码块，脱敏本地路径。
   - `（三）CSM 现场提需的 3 个实战技巧`：提炼可复用的 Prompt 组织技巧（如“附件喂规则、提示词讲骨架”、“埋入未知情况先提醒我的防呆指令”、“先跑通核心链路再套壳交互弹窗”）。
6. **五、踩坑总结与避坑指南**
   - 提炼 3～4 个典型实战坑点（业务规则缺口坑、网页控件/跨月坑、主子流程传参/代码调试坑、自定义对话框/文件夹控件坑），每条严格按 **“踩坑现象 → 解决过程 → 避坑建议”** 展开，并紧邻附上对应截图。

## 四、飞书云文档创建与视觉核验（Step 4）

统一使用 `lark-cli`（遵循 `lark-doc` XML 规范）创建飞书云文档：

1. **初始化草稿工作区**：
   ```bash
   lark-cli docs +script --command init-draft --presentation-decision '{
     "audience": "影刀内部 CSM、售后顾问与培训讲师",
     "reader_task": "快速检索并理解业务场景痛点、解决方案与价值对比，直接参考需求规格、提示词与避坑指南在客户现场演示或复现 AI 流程助手搭建",
     "genre_contract": "router.knowledge",
     "adapter": null,
     "presentation_mode": "rich",
     "visual_plan": {
       "reason": "使用流程图画板直观展示完整业务与自动化链路，配合真实界面与调试截图、结构化对比表展示方案价值与踩坑细节",
       "blocks": [
         {"type": "whiteboard", "min_count": 1, "purpose": "展示从参数输入、网页获取、规则清洗到标准模板落盘的完整流程图"},
         {"type": "img", "min_count": 4, "purpose": "展示规则原表、运行参数弹窗、实跑日志、AI交互与报错修复过程"}
       ]
     }
   }' --format json
   ```
2. **编写并校验 XML 草稿**：
   - 将完整 XML 写入返回的 `draft_path`，执行语法与结构校验：
     ```bash
     lark-cli docs +script --command parse --content "@./<draft_path>" --format json
     ```
   - 确认 `data.assessment.status == "passed"`。
3. **创建飞书文档**：
   ```bash
   lark-cli docs +create --as user --doc-format xml --content "@./<draft_path>" --format json
   ```
4. **画板预览图导出与视觉必检（不可跳过）**：
   - 从 `docs +create` 返回的 `new_blocks` 中找到 `block_type == "whiteboard"` 的 `block_token`，导出预览图：
     ```bash
     lark-cli whiteboard +export --as user --whiteboard-token "<board_token>" --output-type preview --output ./<work_dir>/whiteboard_preview.jpg
     ```
   - 查看 `whiteboard_preview.jpg`，检查标题、卡片内文字及底部深色数据横幅是否存在文字超框、重叠或截断。若发现超框，立即调整 SVG 字号或精简文案，通过 `lark-cli docs +update --as user --doc "<doc_url>" --command block_replace --block-id "<whiteboard_block_id>"` 替换并再次导出核验，确保视觉完美后向用户交付飞书文档链接。

# 浏览器审核台

为新人员建库、扩充候选声纹或操作审核服务时，阅读本文档。

## 控制台页面

首页名称为“声纹建库控制台”，左侧导航包含“概览”“建库任务”和“声纹档案”；新建任务使用独立页面，后续可以继续增加分析报告或运行监控等模块。任务列表以客户名、录音名称、录音数量和中文状态展示，不把长会话 ID 作为主标题。

进入任务后会切换到全屏审核模式：左侧是按录音来源分组的转写标签，中间是聚类和片段，右侧是建库进度、人员管理和确认操作。左右分隔线可拖动或使用方向键调整宽度，双击或点击“恢复默认布局”可恢复；两侧也可以独立收起。布局偏好保存在本机浏览器中，窄屏会自动改为覆盖式侧栏。

审核中的新增人员可以用行末的删除图标移除。若已经分配片段，确认提示后会同步清除这些分配并恢复为“不纳入建库”；正式参会名单或已有声纹人员不会通过该入口删除。点击“确认建库”仍是唯一写入正式声纹版本的操作。

## 网页首次建库

1. 先将录音和对应转写放入 `<客户根>/<客户名称>/` 下的任意子目录；网页不会上传或复制文件，只会选择该客户目录中已有的文件。
2. 打开审核台。客户下拉框会实时读取 `<客户根>` 的直接子目录，自动排除 `共享数据`；这一步只读取目录，不写入 SQLite 或创建声纹数据。用户提交“开始准备审核包”后，系统才为该客户创建声纹数据目录和 SQLite 客户记录，不需要先通过 OpenClaw 创建客户。
3. 选择客户后，“建库素材”会自动加载该客户目录内的**全部录音**，并按“同一路径 + 同文件名（扩展名不同）”自动配对转写。录音文件名会自动成为该场录音的标题和内部标识，因此无需填写会议名称或会议 ID。没有匹配转写的录音会保留在列表中，方便手动补选或直接移除；也可手工新增一组素材。
4. 每份素材右侧的淡色 `⌕` 图标可只读预览对应转写，方便在创建前确认配对是否正确。预览只允许读取当前客户目录中已列出的转写文件，且不会上传或复制原文。
5. 填写参会人的真实姓名、职位和所属方（客户、我方或外部）。姓名不必和飞书转写标签一致；例如转写中的“说话人 1”可在下一步被分配给“张总”。姓名完全一致时仅会作为一个确定性的建议线索。若想快速建立待映射名单，可点击“批量添加”：系统扫描当前已加载的全部转写，提取行首 `说话人 N 时间戳` 中的 `说话人 N`，以“职位留空、所属方为客户”的形式加入列表。它只在点击时执行，后续手工新增素材不会自动补充；重复点击也不会添加同名标签。
6. 点击“开始准备审核包”。多份录音会在同一会话中分别分段、聚类和试听，最终按用户选定的真人汇总，只创建一次首版 `v0001`。每个片段和正式声纹均保留其来源录音和时间戳。

点击后不需要再创建或打开新的任务：页面会自动轮询。`queued` 或 `preparing` 表示后台唯一的声纹 Worker 正在处理；出现 `review_required` 后当前页面会自动切换到审核页。接着按下节完成试听（可选）、分配、校验和确认建库。

### 准备时怎样取样

系统会先对全部转写片段做一次低成本的语音活动与音质筛选，排除静音、音量太低、削波或时长不合格的窗口；因此它不会因为长录音而忽略后半场的有效语音。昂贵的声纹向量提取则按“**每份录音 × 每个原转写标签**”独立限额：首轮数量为 `有效语音秒数 ÷ 30` 向上取整，最少 8 段、最多 24 段；少于该数量时全部保留。选段覆盖该标签的前、中、后时间区间，并优先选择质量较高的窗口。

如果首轮向量显示同一标签有两个占比显著的声纹聚类，系统只会为该标签额外补取最多 8 段，最终不超过 42 段，以便审核混合风险。页面的标签列表会显示“已取样 / 全部合格窗口”，可见本次实际送入声纹模型的数量。正式建库仍会在用户确认的片段中执行内部一致性筛选，最多写入 30 个参考窗口。

## 审核包操作

1. 左侧按录音来源分组展示待审核标签，先查看语音量、风险和已有声纹的 Top-1/Top-2。标签被整组或逐段分配过后会显示“已操作”。
2. 中间默认展示每个聚类的代表片段。绿色标签可按需试听；黄色或红色标签建议试听代表片段，并在必要时展开全部窗口。播放按钮为图标，同一时间只会播放一个片段；播放另一个片段会自动暂停前一个。
3. 将确定属于同一人的聚类整组分配给参会人；下拉项会同时显示姓名和职位。标签混合时，只分配已确认的单个片段。无法确认的内容标记为 `未知`、`路人/杂音` 或 `暂不建库`。
4. 右侧顶部的“建库进度”实时显示每个人已选中的片段数和有效语音秒数；每人至少需要 6 个内部一致的有效窗口、合计 12 秒有效语音。下方可新增客户人员或我方人员：客户人员只存入当前客户，我方人员进入全局员工库。无需填写确认人；确认建库按钮就是正式生效动作。试听不是强制条件，但会保留播放次数。

点击“确认建库”即为正式授权。系统会再次校验全部来源录音和转写未变化，随后原子写入声纹版本；准备阶段的待审核向量会被清理。

## 何时创建审核会话

只要可能创建或扩充声纹档案，就应使用审核会话。准备 Worker 可以基于已知标签映射、精确姓名标签或现有声纹给出身份建议，但该建议绝不会直接写入声纹档案。

```text
speaker_insights.py --customers-root <客户根> enroll review-create \
  --manifest /absolute/path/meeting.yaml --base-url http://192.168.31.169:8765
```

将 `review_url` 返回给用户。不要在聊天中逐个标签提问确认。用户无需试听片段即可提交；审核记录会保留播放次数，但不会因此增加第二次审批步骤。

页面允许将片段分配给参会人、`未知`、`路人/杂音` 或 `暂不建库`，并支持新增客户人员或我方人员。多个标签或聚类可以归属同一人。提交声纹档案时，必须至少有 6 个内部一致、合计 12 秒的有效窗口，且源录音和转写的哈希仍须一致。

## 会话状态流转

```text
queued → preparing → review_required → committing → committed
```

`failed`、`cancelled`、`expired` 和 `source_changed` 状态均不可提交。会话取消或过期后会删除待审核向量；原始文件和最小审计记录会保留。重复提交具有幂等性，将返回相同结果。

在 `queued`、`preparing` 或 `review_required` 时，可以点击页面中的“取消任务”。取消不会创建或修改正式声纹；正在提取向量的任务会在最多 4 个窗口后协作停止。取消后可直接重新创建新任务。

审核台统一显示中文状态：`排队中`、`准备中`、`待审核`、`正在建库`、`已建库`、`已取消` 等。准备中会显示当前阶段：加载模型、转码第几份录音、筛选有效语音、当前声纹窗口处理数、疑似混合标签补样以及审核包写入。进度写入 SQLite，因此刷新页面后仍可查看。

已取消的“首次建库”任务可点击“按原素材重新开始”。系统会用原来的录音、转写和参会人清单新建一个会话并重新计算；不会复用旧临时向量，也不会覆盖原已取消任务的审计记录。

## 服务操作

Mac（按需启动）：

```text
speaker_insights.py --customers-root /Users/velen/Desktop/Velen/Z7Z8/客户 \
  review serve --host 127.0.0.1 --port 8765 --base-url http://127.0.0.1:8765
```

Ubuntu 运行对应的 systemd 用户服务。它只绑定配置的局域网地址，并使用一个含 3 个 Torch CPU 线程的 Worker。API 不开放 CORS，并使用同站 CSRF 令牌；这不能替代网络隔离。

## 候选扩充与声纹管理

通过 `profile candidates --customer ID` 列出候选声纹，再用下列命令创建浏览器审核会话：

```text
speaker_insights.py --customers-root <客户根> profile review-create --candidate CANDIDATE.json
```

批准后会创建不可变的 `vNNNN` 新声纹版本。拒绝只会改变候选状态。回滚会修改当前版本指针；隔离会清空该指针，使后续匹配不再加载此人。两种操作都不会物理删除文件。
